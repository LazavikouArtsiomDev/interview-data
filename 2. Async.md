1. Что такое асинхронное программирование в Python?
    1. **Парадигма программирования, позволяющая выполнять несколько операций "одновременно" без использования многопоточности в традиционном смысле**
    2. Вместо того чтобы ждать завершения одной операции, прежде чем начать следующую, асинхронный код может переключаться между разными задачами, пока они ожидают завершения операций ввода-вывода
2. Как работают ключевые слова `async` и `await`?
    1. `async` определяет функцию как функцию-корутину. Корутина — это объект, который может быть приостановлен и возобновлён в определенных точках
    2. `await` используется внутри `async` функций для приостановки выполнения корутины до завершения определенной асинхронной операции. `await` может быть применен только к _awaitable_ объектам, таким как другие корутины или объекты, возвращаемые асинхронными функциями. Пока ожидаемая операция выполняется, управление возвращается в event loop, который может запустить выполнение других корутин
3. Что такое асинхронные операции ввода-вывода и чем они отличаются от синхронных операций?

5. Какие отличия CPU-bound и IO-bound операций?    
    1. IO-bound - операции, которые большую часть времени тратят на ожидание внешних ресурсов, например, сетевых запросов, чтения файлов или взаимодействия с базой данных
    2. CPU-bound не получают значительного прироста производительности от использования асинхронщины, потому что процессор и так занят обработкой задачи. Тут нужна многопроцессность
6. `Multiprocessing` vs `multithreading` vs `asyncio`:    
    1. `Multiprocessing`: Запускает несколько процессов, каждый со своей отдельной памятью и интерпретатором Python. Обходит GIL, подходит для CPU-bound задач, но имеет большие накладные расходы на создание и управление процессами
    2. `Multithreading`: Запускает несколько потоков в рамках одного процесса. Не обходит GIL, поэтому для CPU-bound задач в Python неэффективен. Подходит для IO-bound задач, где потоки большую часть времени проводят в ожидании
    3. `Asyncio`: Использует корутины и один поток для достижения конкурентности. Идеально подходит для IO-bound задач, эффективно использует ресурсы и имеет меньшие накладные расходы, чем `multiprocessing` и `multithreading` в случае IO-bound задач. Не подходит для CPU-bound задач
7. GIL (Global Interpreter Lock):    
    1. механизм в CPython (стандартной реализации Python), который позволяет только одному потоку выполнять байт-код Python одновременно. Это упрощает управление памятью, но ограничивает истинную параллельность выполнения Python-кода на нескольких ядрах процессора. GIL не влияет на `asyncio`, так как `asyncio` использует один поток и конкурентность достигается за счет переключения между корутинами
8. Как работает однопоточная конкурентность?    
    1. Однопоточная конкурентность, реализуемая asyncio, **основана на кооперативной многозадачности (есть ещё простое переключение человеком и вытесняющая многозадачность). Корутины _добровольно_ отдают управление циклу событий с помощью `await`, позволяя другим корутинам выполняться**. Это отличается от вытесняющей многозадачности, используемой в многопоточности, где операционная система принудительно переключает контекст между потоками

10. Как работает под коробкой цикл событий? Сколько видов цикла событий?    
    ```python

         """Run one full iteration of the event loop.
         
         This calls all currently ready callbacks, polls for I/O,
         schedules the resulting callbacks, and finally schedules
         'call_later' callbacks.
         """

    1. работа
        1. **Регистрация корутин:** Корутины регистрируются в цикле событий для выполнения.
        2. **Выполнение корутин:** Цикл событий выбирает готовую к выполнению корутину и запускает ее.
        3. **Ожидание:** Когда корутина достигает `await`, она приостанавливает свое выполнение и возвращает управление циклу событий.
        4. **Обработка событий:** Цикл событий проверяет наличие завершенных операций ввода-вывода или других событий.
        5. **Возобновление корутин:** Когда ожидаемая операция завершается, цикл событий возобновляет выполнение соответствующей корутины.
    2. виды
        1. **`asyncio.SelectorEventLoop` (по умолчанию):** Основан на селекторах операционной системы (`select`, `poll`, `epoll` или `kqueue`). Эффективен для большого количества одновременных соединений.
        2. **`asyncio.ProactorEventLoop` (Windows):** Использует асинхронные операции ввода-вывода, предоставляемые операционной системой Windows. Более эффективен для Windows, чем `SelectorEventLoop`.
        3. **Высокопроизводительные циклы событий сторонних библиотек:** Например, `uvloop` (основан на `libuv`, той же библиотеке, что и Node.js) может значительно увеличить производительность asyncio.

import concurrent.futures
import time

def fetch_data(id):
    print(f"Fetching data for task {id}...")
    time.sleep(2)  # Simulate a network delay
    return f"Data for task {id}"

def main():
    # Create a ThreadPoolExecutor
    with concurrent.futures.ThreadPoolExecutor(max_workers=5) as executor:
        # Submit tasks to the executor
        futures = {executor.submit(fetch_data, i): i for i in range(5)}

        # Process the results as they complete
        for future in concurrent.futures.as_completed(futures):
            task_id = futures[future]
            try:
              # Get the result of the task
                result = future.result()
                print(f"Task {task_id} completed: {result}")
            except Exception as e:
                print(f"Task {task_id} generated an exception: {e}")

if __name__ == "__main__":
    main()
```
19. В чем разница между конкурентностью и параллельностью?
    1. **Конкурентность (Concurrency):** Способность программы обрабатывать несколько задач _логически_ одновременно. Задачи могут выполняться по очереди, быстро переключаясь между ними, создавая иллюзию одновременного выполнения. Asyncio реализует конкурентность в одном потоке. GIL не препятствует конкурентности, так как корутины сами отдают управление.
    2. **Параллелизм (Parallelism):** Способность программы выполнять несколько задач _физически_ одновременно, используя несколько ядер процессора. Multiprocessing реализует параллелизм. GIL препятствует истинному параллелизму в многопоточности, так как только один поток может выполнять байт-код Python в каждый момент времени.

38. Как работает thread locals?    
    1. Thread locals — это механизм, который позволяет хранить данные, специфичные для каждого потока. Каждый поток имеет свой собственный словарь thread locals, который доступен через `threading.local()`. Это полезно, когда нужно хранить данные, которые не должны быть общими для всех потоков, например, контекст запроса в веб-приложении    
    ```python
    import threading
    
    thread_local_data = threading.local()
    
    def worker(num):
        thread_local_data.value = num
        print(f"Thread {num}: value = {thread_local_data.value}")
    
    threads = []
    for i in range(2):
        t = threading.Thread(target=worker, args=(i,))
        threads.append(t)
        t.start()
    
    for t in threads:
        t.join()
    ```
