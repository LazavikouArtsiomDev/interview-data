12. Что такое декоратор и как он реализуется в Python?
     1. **Паттерн, заключающийся в дополнении функционала функции**
     2. Декоратор при помощи класса делается при помощи `__call__`
     3. Параметризованный декоратор делается при помощи добавления ещё одной функции-обёртки, которая принимает собственно параметры и возвращает функцию, которая в свою очередь принимает функцию
          ```python
          def repeat(times):
               def decorator(func):
                    def wrapper(*args, **kwargs):
                         for _ in range(times):
                              result = func(*args, **kwargs)
                         return result
                    return wrapper
               return decorator
          ```
     4. [Вроде нормальная ссылка](https://realpython.com/primer-on-python-decorators)
     5. функция, которая принимает другую функцию в качестве аргумента и расширяет её функциональность, не изменяя ее код напрямую
     ```python
     def my_decorator(func):
          def wrapper():
               print("Перед вызовом функции")
               func()
               print("После вызова функции")
          return wrapper
     
     @my_decorator
     def say_hello():
          print("Привет!")
     
     say_hello()
     ```

20. Работа декоратора `@property` в Python?
     1. используется для создания методов, которые ведут себя как атрибуты класса (геттеры и сеттеры)
          ```python
          class Circle:
               def __init__(self, radius):
                    self._radius = radius
               @property
               def radius(self):
                    """Getter for the radius property."""
                    return self._radius
               @radius.setter
               def radius(self, value):
                    """Setter for the radius property."""
                    if value < 0:
                         raise ValueError("Radius cannot be negative.")
                    self._radius = value
               @property
               def area(self):
                    """Computed property for the area of the circle."""
                    return 3.14159 * (self._radius ** 2)
          ```

24. Как работают значения по умолчанию в `dataclasses`?

          3. `init`: Use field in `.__init__()` method? (Default is `True`.)


40. Как создать собственный дескриптор?
     1. свойство класса должно иметь значение класса, определяющего эти методы:
     
     ```python
     class TypedProperty:
          def __init__(self, type):
               self.type = type
     
          def __get__(self, instance, owner):
               if instance is None:
                    return self return instance.__dict__[self.name]
     
          def __set__(self, instance, value):
               if not isinstance(value, self.type):
                    raise TypeError(f"Ожидался тип {self.type}")

               self.name = name
     
     class Person:
          name = TypedProperty(str)
          age = TypedProperty(int)
     
     ```
     
41. Что такое метапрограммирование и как оно используется в Python?
     1. **Метапрограммирование — это написание кода, который манипулирует другим кодом**
     2. Метаклассы, декораторы, интроспекция (получение метаданных об объектах, например, при помощи `__name__`, `__doc__`, `help()`)
     
     ```python
     class AddMethodMeta(type):
          def __new__(cls, name, bases, attrs):
          # `bases` contains base classes of class being created
          # `attrs` contains dict with all properties
               attrs['say_hello'] = lambda self: print(f"Hello from {self.__class__.__name__}!")
               return super().__new__(cls, name, bases, attrs)
     
     class MyClass(metaclass=AddMethodMeta):
               xd = 1
          pass
     
     class MyOtherClass(metaclass=AddMethodMeta):
          def some_method(self):
               print("This is some_method")
     
     instance1 = MyClass()
     instance2 = MyOtherClass()
     
     instance1.say_hello()  # Output: Hello from MyClass!
     instance2.say_hello()  # Output: Hello from MyOtherClass!
     instance2.some_method() # Output: This is some_method
     ```

80. `raise ... from`?
  1. Механизм для связывания исключений в цепочку. Позволяет указать, при обработке какого исключения возникло другое исключение
     1. Three attributes on exception objects provide information about the context in which the exception was raised:
          1. `BaseException.__context__`
          2. `BaseException.__cause__`
          3. `BaseException.__suppress_context__`
     2. When raising a new exception while another exception is already being handled, the new exception’s `__context__` attribute is automatically set to the handled exception. An exception may be handled when an `except` or `finally` clause, or a `with` statement, is used. This implicit exception context can be supplemented with an explicit cause by using `from` with `raise`: `raise new_exc from original_exc`
     3. The expression following `from` must be an exception or `None`. It will be set as `__cause__` on the raised exception. Setting `__cause__` also implicitly sets the `__suppress_context__` attribute to `True`, so that using `raise new_exc from None` effectively replaces the old exception with the new one for display purposes (e.g. converting `KeyError` to `AttributeError`), while leaving the old exception available in `__context__` for introspection when debugging.
     4. The default traceback display code shows these chained exceptions in addition to the traceback for the exception itself. An explicitly chained exception in `__cause__` is always shown when present. An implicitly chained exception in `__context__` is shown only if `__cause__` is `None` and `__suppress_context__` is `false`.
     5. In either case, the exception itself is always shown after any chained exceptions so that the final line of the traceback always shows the last exception that was raised.

          2. `D` is added (it's not in `[E, B, C]`): `[F, D]`

          6. `C` is added: `[F, D, E, A, B, C]`
          7. C3 по факту - поиск в глубину, но если какой-то класс встречается несколько раз, то остаётся только его последнее вхождение в строку

     ```
          pass
     class B:
          pass
     class C:
          pass
     class D(A, B):
          pass
     class E(B, C):
          pass
     class F(D, E):
          pass
     ```

          1. поиск в глубину (простой, как палка)
87. Выделение памяти в Python?

          2. Пул — это блок памяти, который содержит объекты одного размера (размер определяется Python). (4кб, одна страница)

          4. Пул флаги — каждый пул помечается в зависимости от того, насколько он заполнен (например, частично заполнен или полностью свободен)

89. Сборка мусора?
     1. **Процесс автоматической проверки объектов на предмет того, используются ли они в программе, и очистка памяти от ненужных объектов**
     2. сборщик мусора фокусируется только на объектах, которые могут содержать ссылки на другие объекты (словари, объекты классов, массивы и т.д.)
     3. СМ должен пройтись по всей куче, такой проход называется полной очисткой
          1. перед каждой очисткой все объекты в куче считаются непосещёнными
          2. выполняется как серия инкрементальных очисток
               1. “новые” объекты
               2. “старые” объекты, которые дольше всех не посещались
               3. все объекты, достижимые из этих объектов и ещё не посещённые за эту полную очистку
     4. Когда количество ссылок на объект становится равным нулю, сборщик мусора удаляет этот объект и освобождает занимаемую им память
     5. также проверяется доступность из случайных (в базовой сборке) или всех (в сборке без GIL) узлов графа доступность узлов на случай отделённых циклических графов, не связанных с остальной частью
     6. Начиная с версии 3.13, есть две реализации СМ:
          1. потокобезопасная, когда GIL включён
          2. тоже потокобезопасная (потому что админским произволом останавливает все потоки выполнения на время сборки мусора), когда GIL выключен (не использует инкрементальную очистку, каждый раз смотрит всю кучу)
